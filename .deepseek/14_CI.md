## §14.1 Job layout

| Job | Runs on | Purpose |
| --- | --- | --- |
| `python` | `ubuntu-latest` + `actions/setup-python` (3.12, 3.13) | pytest, coverage (A1, A2–A6, A9) |
| `lint` | `ubuntu-latest` | ruff, black, mypy (A1) |
| `notebooks` | `ubuntu-latest` | nbmake over `python/notebooks/` (A9) |
| `colcon` | `ubuntu-latest` + `ros:lyrical-ros-base` container | OSQP, build, gtest suite, **and the A7 parity test** (A1, A7, A8) |
| `docs` | `ubuntu-latest` + TeX Live | compile the three derivations |

**The runner is `ubuntu-latest`, not `ubuntu-26.04`, deliberately.** The container supplies Ubuntu
26.04 regardless of the host image, and an `ubuntu-26.04` runner label may not exist (risk V1). Do
not "fix" this by pinning the runner unless you have confirmed the label. Keep a comment in the
workflow saying so.

`ROS_DISTRO: lyrical` SHOULD be a workflow-level env var so the distro name appears once rather than
in five places.

The Python matrix MUST match `requires-python` in `pyproject.toml`
([03_BUILD_SYSTEM.md §3.5](03_BUILD_SYSTEM.md)). Three places, one fact.

Target: the whole workflow under ~15 minutes. Beyond that people stop reading it.

## §14.2 Test selection and caching

Pull requests run `-m "not slow"`; pushes run the full suite. The `@slow` marker exists so the PR
loop stays fast ([10_TESTS.md §10.6](10_TESTS.md)), not so slow tests can be skipped indefinitely.

Cache pip on the hash of `pyproject.toml`. Cache the OSQP build (if built from source, §14.3) keyed
on **the OSQP tag *and* the container digest**.

**Do not key a cache on the OS alone.** A stale cache of a source build is how you end up testing
last month's solver against this week's formulation, and the symptom is a parity failure that looks
like a bug in the controller.

## §14.5 A7 and A8 — what CI does and does not own

**A7 (parity) is CI's job.** The parity test runs in the `colcon` job, because that is where the
built C++ test binary and its `test/data/four_agent_reference.json` fixture exist. `colcon test`
already runs it as part of the gtest suite.

If it silently skips — a missing fixture, a `GTEST_SKIP` — then A7 is **not verified by CI** while
the badge suggests otherwise. Assert the fixture's presence in the workflow, or say in the README
that A7 is verified locally only. Do not let the badge imply something that is not happening.

**A8 (timing) is not CI's job.** Shared runners give timings that vary by several multiples. Assert
a generous ceiling in CI to catch a catastrophic regression, and take the real p95 from a local
Release run with the CPU named ([10_TESTS.md §10.4](10_TESTS.md)). A CI-derived solve time in the
README would be a number you cannot defend.

`NoHeapAllocationDuringIterate`, by contrast, **is** deterministic and belongs in CI.

## §14.7 Test results and diagnosis

`colcon test --return-code-on-test-failure` followed by `colcon test-result --verbose`. Both are
needed: the first fails the job, the second prints *what* failed. Dropping the second produces a red
job with no diagnosis, which trains everyone to re-run rather than read.

Upload test results with `if: always()` so a failing run still yields its XML.

## §14.8 What is deliberately absent

- **No coverage gate.** Coverage on a library this size measures how many lines the randomised
  convergence campaign happened to touch, which is not a quality signal. The centralised
  cross-check (A2) and the C++/Python parity check (A7) are the real coverage argument.
- **No auto-format commit.** Linting fails the build; it does not rewrite your code.
- **No headless launch smoke test yet.** The nearest equivalent — running
  `4_agent_admm.launch.py` for a fixed duration and asserting the final formation error — is worth
  adding once §11 is stable and would upgrade A4 confidence considerably. Until then that check is
  manual, and the README must not imply otherwise.
- **No committed `media/`regeneration in CI.** The GIFs are large binaries; regenerating them per
  push would bloat the repository. `media/README.md` records how to regenerate them
  ([§12.9](12_ANALYSIS.md)), and the release checklist ([15_ROADMAP.md §18](15_ROADMAP.md)) checks
  that they still can be.
