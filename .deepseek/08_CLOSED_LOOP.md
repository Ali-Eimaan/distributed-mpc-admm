## §8.1 The receding-horizon loop

Each control step `k`:

1. `graph = schedule.at(k)`; rebuild the solvers whose closed neighbourhood changed (§8.2)
2. build per-agent references from `leader_follower` ([07_FORMATION.md §7.4](07_FORMATION.md))
3. `result = admm.solve(x, refs, offsets, initial_guess=prev.shifted() if warm_start else None)`
4. `u = result.first_inputs()`
5. advance the **true** plant with `u`, add process noise
6. log states, inputs, predictions, iterations, formation error, the active graph, the history

Apply the input to the true state, never to the predicted one. Add process noise **after** the
dynamics update; add measurement noise only to what is passed into the next solve. Conflating the
two makes the noise study meaningless — one is a plant property and the other is a sensing property,
and they have different effects on warm-start quality.

## §8.2 `DistributedMPC`

Cache solvers keyed by `(agent_id, neighborhood)`:

```python
self._solver_cache: dict[tuple[int, tuple[int, ...]], PerAgentSolver] = {}
```

`_rebuild_solvers(graph)` rebuilds **only** agents whose closed neighbourhood changed. Constructing a
`CvxpyAgentSolver` compiles a CVXPY problem; rebuilding all `N` at every switch dominates the
runtime of the switching notebook and makes the dwell-time sweep in [§12.4](12_ANALYSIS.md)
impractically slow.

At a switch, `FormationSpec.validate_against(graph)` may raise
([07_FORMATION.md §7.4](07_FORMATION.md)). Catch it here and apply a stated policy: drop the term for
the missing edge and record it in `SimulationLog.metadata`. Whatever you choose, it must be visible
in the log — a formation that silently changes shape at a switch is exactly the kind of result that
survives into a GIF.

`step(k, x)` returns `((N, dim) applied input, ADMMResult)` so a notebook can drive the loop
manually and inspect the intermediate result. `run(x0, n_steps)` is the batch form.

## §8.3 The warm-start shift

`ADMMResult.shifted()` drops row 0 of every `(T, dim)` block and duplicates the last row, returning
`(local_copies, consensus, duals)`.

**Shift the duals the same way.** Zeroing them throws away most of the warm-start benefit and A6
will fail. The duals encode the price of the consensus constraint, which changes slowly between
control steps — that is the whole reason warm starting works here.

A6 asks for a factor of two. In practice a converged warm start typically does much better than
that; the criterion is deliberately loose so it measures "warm starting works" rather than
"warm starting works as well as it did on my laptop".

## §8.4 `SimulationLog`

All arrays indexed by control step. `states` is `(K+1, N, 2·dim)` and **includes the initial
condition** as row 0; `inputs` is `(K, N, dim)`. That off-by-one between them is deliberate and
every consumer must respect it — `positions` is a view of the position rows of `states`, so it is
also length `K+1`.

`summary()` returns the headline numbers for the README table: mean and max ADMM iterations, final
formation error, settling step, total solve time, count of steps that hit the iteration cap. The
last one matters and is easy to omit: a run that converged everywhere and a run that capped out on
30 % of steps can produce indistinguishable trajectories.

`save` / `load` use `np.savez_compressed`. Two fields do not survive `npz` directly:

- `graphs` → serialise as a `(K, N, N)` adjacency stack, rebuild with
  `CommunicationGraph.from_adjacency`
- `histories` → stack the residual arrays plus an index of per-step lengths

**Do not use `pickle`.** These files are committed, regenerated by CI and read by the analysis
notebooks; a pickle is a version-coupled binary that will stop loading and take its results with it.

## §8.5 `plotting.py`

Every function takes an optional `ax` and returns what it drew on, so notebooks can compose
subplots. Nothing calls `plt.show()` or writes a file except the explicit `save_*` helpers.

`AGENT_COLORS` is fixed and MUST stay stable across every figure in the repository. A reader should
be able to identify agent 2 by colour alone in any plot, including in the C++ demo screenshots.

`apply_style(context)`:

| Context | For |
| --- | --- |
| `"paper"` | serif, small — the LaTeX documents |
| `"notebook"` | default sizes |
| `"readme"` | larger fonts, **transparent background** |

The transparent background is not cosmetic. GitHub renders READMEs in light and dark themes; a
white-background PNG in a dark README reads as a rendering bug, and it is the first thing a reviewer
sees.

Figures that carry a specific obligation:

- `plot_inputs` — shade the saturation band. Whether the limits are ever active is the first
  question anyone asks about an MPC result; make it visible rather than asserting it in prose.
- `plot_convergence` — primal solid, dual dashed, tolerances dotted. When `show_rho` is set, add a
  twin axis with the `ρ` trace. **Required whenever adaptive `ρ` is on**, or the residual kinks are
  unexplained.
- `plot_iterations_to_consensus` — always plot the individual trials behind the median. The spread
  across random initial conditions is large and a bare mean curve overstates how clean the result
  is.
- `plot_formation_error` — vertical lines at topology switches.
- `plot_topology_timeline` — one row per edge, shaded where active, with `λ₂` overlaid so the
  connectivity drop at each switch is visible.
- `plot_communication_load` — annotate the `O(N²)` complete-graph curve against the `O(N)` sparse
  ones. This plot is the argument for why distribution is worth the trouble.

## §8.6 Animation and media

`animate_formation` builds a `FuncAnimation`: agent markers, fading trails, faint predicted
horizons, optional communication edges, and a corner box with `t`, ADMM iterations at that step and
formation error.

**Use `blit=False`.** The edge collection changes cardinality between frames when the topology
switches, which blitting cannot handle. The symptom is edges that persist after they should have
disappeared — which, in a GIF whose entire subject is topology switching, is a fatal artefact.

`save_animation` infers GIF (Pillow) or MP4 (ffmpeg) from the extension. Keep GIFs under about 5 MB
or GitHub will not autoplay them: cap the figure at ~7 inches, `dpi ≤ 110`, and **subsample frames
rather than dropping fps below ~15** — a choppy GIF reads as a broken demo.

`make_readme_media(log_4agent, log_switching, out_dir)` regenerates everything in `media/` and is
what `python -m distributed_mpc_admm.plotting` calls. The committed media must always be
reproducible from committed code ([§12.9](12_ANALYSIS.md)).

## §8.7 Tests owned by this section

In `python/tests/test_formation_consensus.py` ([§10.2](10_TESTS.md)):

- `test_agents_reach_formation` — **A4**. Assert on the *held* error over the last 20 % of the run,
  not the final sample.
- `test_warm_start_reduces_iterations` — **A6**. Perturb `x₀` between the two solves so the test is
  not trivially satisfied by an unchanged problem.
- `test_formation_holds_while_tracking` — bounded centroid lag, **not zero lag**. This is a
  finite-horizon tracker with no integral action; asserting zero lag would be asserting a property
  the controller does not have.
- `test_leader_only_tracks_reference` — followers have zero tracking weight and still move. This is
  what proves the formation coupling, not the reference, is doing the work.
- `test_formation_recovers_after_topology_switch` — the error **spikes** at the switch and settles
  again. Both halves matter: a run with no spike means the switch was not actually applied.
- `test_simulation_log_roundtrip` — `save`/`load` preserves every array exactly, including `graphs`
  and `histories`.

Plotting functions are not unit-tested beyond "returns an `Axes` and does not raise". The real test
of the figures is that the notebooks execute in CI ([§14.4](14_CI.md)).
